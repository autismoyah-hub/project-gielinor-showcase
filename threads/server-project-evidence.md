# Server project thread: evidence and scope

Reviewed 2026-10-19 (America/Los_Angeles). This accompanies the main server thread; it is not a separate Tower thread. Images are development checkpoints, not full functional parity.

## What the images are

The gallery has nine Rust-server captures and two explicitly labelled Kotlin-reference captures. New bank, copper-mining and herb-cleaning images come from scripted native-client integration runs over real TCP sessions with immutable historical Rust server executables. They use actual native menus and assert received results. These are prepared demonstrations on disposable, offline-seeded accounts, not manual end-to-end playtests or proof of normal item acquisition. Other headless rule tests are discussed in prose and are not presented as gameplay screenshots.

The food and wine images are UI-focused independent verification frames with incomplete scene cameras; captions retain that limitation. We excluded blank scene-only equipment captures and repetitive failed camera probes. No generated, retouched or reconstructed gameplay image is included. PNG encoding preserves the original rendered RGB pixels and dimensions and removes metadata. The [image manifest](../images/server-openrune/MANIFEST.json) records hashes, server/commit identities, source run identifiers and limitations without private filesystem paths.

## Implementation and history reviewed

The implementation review is pinned to [82888b93](https://github.com/autismoyah-hub/project-gielinor-rust-server/tree/82888b93d619cd03facf1bf022d79078ab97f1e3). It covers the foundational Rust server history, native integration journals, differential-test records, actual startup/action registration and the later OpenRune implementation queue. The checkpoint includes [ordinary selected spade Dig](https://github.com/autismoyah-hub/project-gielinor-rust-server/commit/cec5b1e125021b606371fc70488a67635b7213c9). The screenshots deliberately use several earlier builds; they do not inherit the latest checkpoint's scope.

- **Networking, login and persistence:** transport/session/authentication and SQLite character-save paths; actual native login and saved-state campaigns. Early framing and integration failures were corrected and retained in the history. Full reconnect/soak coverage is not implied. See [native integration history](https://github.com/autismoyah-hub/project-gielinor-rust-server/blob/82888b93d619cd03facf1bf022d79078ab97f1e3/docs/INTEGRATION.md).
- **Simulation, movement and NPC synchronization:** authoritative world phases, protected action queues, collision/routing, player and NPC update paths. Historical native world captures and later native movement/search campaigns supplement headless tests. A still frame is not a synchronization stress test.
- **Inventory, equipment and banking:** runtime wiring, selected-slot checks, item conservation, native bank actions and earlier same-save bank login tests. The new bank showcase run itself is only a same-session transfer/display check. Full equipment and every bank control are not visually demonstrated here.
- **Combat, magic, ranged and prayer:** implemented calculation, equipment, rune/ammunition, spell, XP and prayer selection/drain paths with development/differential tests and runtime configuration. Broad native encounter/loot acceptance remains incomplete. The two combat pictures are Kotlin-reference client comparison captures, not Rust-server proof. See [startup registration](https://github.com/autismoyah-hub/project-gielinor-rust-server/blob/82888b93d619cd03facf1bf022d79078ab97f1e3/crates/server/src/startup.rs).
- **Gathering and processing:** selected mining/woodcutting targets and tools, depletion/restoration and XP rules; smelting/smithing material/failure checks. The fresh mining run exercised one prepared copper target and observed one ore, displayed XP growth, depletion and respawn. It does not validate all rocks, authoritative fine XP/cadence or ordinary tool acquisition.
- **Cooking and crafting:** registered cooking/baking, dough/pie assembly, gem cutting, glassblowing, pottery, jewellery, spinning, weaving and selected leatherwork. Tests and exact recipe contracts define scope; these are not complete-skill claims. See [content adapters](https://github.com/autismoyah-hub/project-gielinor-rust-server/tree/82888b93d619cd03facf1bf022d79078ab97f1e3/crates/server/src/content).
- **Food, potions and Herblore:** selected food stages/stat effects/container returns, herb cleaning, unfinished/finished potion paths, grinding and dose upgrades. The fresh herb run cleaned only selected marrentill and guam in a full backpack and checked their output/XP. Earlier unfinished-potion native logs cover selected ingredient/output flows; no potion screenshot was fabricated from those logs.
- **Shops, packs and item interactions:** shop stock/transaction/session primitives and runtime adapter have tests, but named world-shop stock is not broadly registered at this checkpoint. Item packs and selected use-item paths are separate registered content; a tested shop primitive is not evidence of a populated shop world.
- **NPC interactions and loot:** routing/dialogue, selected pickpocketing and death/loot paths exist with tests. An earlier native chicken encounter failed before the required Attack/result observations; it is not presented as successful combat evidence. No whole NPC/loot catalog claim is made.
- **Scenery and OpenRune expansion:** selected searches, pickables, chest/drawer/traversal/signpost/spade implementations are individually registered. Generic spade's actual quest/boss hook consumers remain unported. Registration is not independent acceptance.

The [append-only implementation queue](https://github.com/autismoyah-hub/project-gielinor-rust-server/blob/82888b93d619cd03facf1bf022d79078ab97f1e3/docs/openrune/verification/IMPLEMENTATION_QUEUE.jsonl) and [migration status](https://github.com/autismoyah-hub/project-gielinor-rust-server/blob/82888b93d619cd03facf1bf022d79078ab97f1e3/OPENRUNE_MIGRATION_STATUS.md) retain source commits, registration consumers, tests and unresolved obligations. The discovery inventory classifies source-review work and is not a percentage of gameplay completion.

Exact-build native/lifecycle/source comparisons continue in [verification issue 134](https://github.com/autismoyah-hub/project-gielinor-rust-server/issues/134); other subsystem issues retain their own scope.
